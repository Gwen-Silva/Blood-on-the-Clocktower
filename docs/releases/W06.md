# W06: Character cards and mobile readability

Baseline: `918e2b43e4a8e6d9f9e46c9b9709df13658569e1` on
`release/weekend-2026-10-31`.

## Changes

- RoleCard keeps the complete ability and explicitly selected supporting facts
  visible. The rules action opens a static Radix panel, independently scrollable
  on mobile and centered on desktop. It receives only a role ID and presentation
  context, never a game or player record.
- The panel owns one same-URL history entry. Back closes it before the router or
  private reveal handler. Close, Escape and the existing sheet dismissal use the
  same path. Repeated close requests cannot consume another history entry. Radix
  restores focus to the trigger.
- CardShell grows with content instead of imposing a desktop aspect ratio, with
  padding around decorative corners. OracleCard shares this shell; its reveals
  remain part of browser regression coverage.
- The outer game region owns reference scrolling. An unconstrained inner
  `reference-detail-content` scroller used overscroll containment and swallowed
  native scroll gestures, although programmatic scrollIntoView still worked.
  Removing that redundant inner scroller is covered by a real Chromium wheel
  regression at 320×568; the rules control must reach the viewport before tapping.
- RoleName measures available width and the longest word after font loading and
  resizing. It uses layout widths, independent of the card's entrance scale,
  to keep fitting reliable during animation and at 200% text size. It keeps
  individual words intact and permits multiword wrapping.
- Butler explains permission to vote and the freedom to abstain in all three
  languages. Reference: <https://wiki.bloodontheclocktower.com/Butler>.
- The 22 official Trouble Brewing wiki pages use explicit ID mappings in
  `src/lib/roles/wiki.ts`. All mapped pages were retrieved from the official wiki.
  Villager has no official link. Links open separately with `noopener noreferrer`
  and `referrerPolicy="no-referrer"`; local instructions work without the wiki.
- Home metadata translates phases, including a safe unknown fallback. Only exact
  historical `Game <creation date>` / `Partida <creation date>` patterns receive
  a localized display title. Other custom titles remain literal. This is a
  presentation heuristic: an intentionally custom title identical to an old
  generated title cannot be distinguished without provenance that old saves do
  not contain. Stored names, IDs and history are never rewritten.

## Validation and publication

Run `npm ci`, `npm run tc`, `npm test`, `npm run build`, Prettier on changed files
and `git diff --check`.

`npm run test:e2e` covers static rules in a private reveal, unchanged saves,
Back/Close/Escape, restored focus, an unfinished private reveal, external wiki
referrer isolation, the protected one-second hold with contextmenu, 200% text at
320×568, and the existing Spy handback regression. Use
`PLAYWRIGHT_CHROMIUM_EXECUTABLE` when Chromium is installed outside Playwright's
default location. `E2E_BASE_URL` can target a running preview or deployed release.

The visual acceptance matrix is all 23 roles in PT-BR, EN and ES at 320×568,
360×640, 390×844, 412×915 and 1400×900. Check full abilities, word fitting, card
containment, independently scrollable rules, links and browser Back. Capture
Saint, Imp, Baron, Butler and Librarian before and after. Disable only continuous
card floating during geometry measurements; retain real sheet transitions and
test real touch separately.

Publish only the release branch with a normal authenticated Git push. The Pages
workflow runs tests, typecheck and production build before deployment. Verify
`git ls-remote`, the Actions deployment and the public About build SHA. Do not
force-push or change main, rebuild or draft PR #2.

Chromium mobile touch emulation is browser evidence, not physical Android or
installed-PWA validation. The latter must be reported separately as NOT RUN when
no device is available. PWA update behavior and saved-game formats are unchanged.

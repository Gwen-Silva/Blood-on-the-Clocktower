# W08: Focused UI refinement and safe startup

Baseline: `4c97fdc0bc3332edf000b8f2bd9f5b29bb478e4f` on
`release/weekend-2026-10-31`.

## Startup investigation

The W07 public build reproduced the reported recovery screen after interrupting
a player-facing session. A clean profile opened home normally; a completed
one-second handback removed the latch and reopening home did not ask again.
Stale protection after a legitimately completed handback was not reproduced.
The actual history of a user's device cannot be inferred from the deliberately
opaque, non-null protection marker.

The latch is not cleared on home, navigation, unmount, reload or restart. Its
registration/release logic and W02 hold cancellation logic are unchanged.
AudienceRecoveryBoundary now selects a neutral, branded recovery presentation
that explains the pending confirmation. The same full 1,000 ms hold is required.
Ordinary in-session handback keeps its existing presentation.

Checks include real browser-process closure/reopening with a persistent profile,
and an additional private reveal interruption in a profile controlled by an
activated service worker. Interrupted recovery stayed protected; after the hold,
another cold reopening reached home without a latch. Installed standalone PWA
display mode and physical Android were not exercised.

## Focused interaction changes

- GameScreen uses one scoped, non-wrapping toolbar. Reference has a short visible
  label and its full accessible name. Language selection uses the globe; private
  controls retain their labels. Below 360px, icons retain full accessible names.
  All targets remain at least 44×44 CSS pixels. The content occupies its own row.
- Completed revelation rows retain the green check. The repeated instruction is
  in the accessible row name, with player and character, rather than visible
  alongside the player's name. Border widths stay aligned and repeat revelation
  still uses the protected audience lifecycle.
- Information results use a styled character action with localized View/Hide
  labels, an icon/chevron, aria-expanded and aria-controls. The approved card
  remains unchanged. Toggling has no completion callback or save side effect;
  Continue still requests protected handback. No new modal/navigation level was
  added for the expander.

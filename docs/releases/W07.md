# W07: Categorized role library and navigation

Baseline: `c9e36b018a77aecc065a9a6181738331a99ccf7f` on
`release/weekend-2026-10-31`.

## Interface

The landing screen has four team cards using existing icons, colors and localized
plural labels. Counts come from registered definitions in the selected static
script: Trouble Brewing has 13/4/4/1; Custom includes Villager. Selecting a team
shows only its characters. A compact native category picker remains available
while scrolling, including at enlarged text sizes. Previous/next stays within
the selected category and is disabled for a one-character category.

## Navigation state

`roleLibraryNavigation.ts` owns UI-only history entries and bounded memory caches.
Entries carry a browsing-session identifier, script, view, category, character,
scroll offset and focus target. They contain no game IDs, player records,
assignments, effects or Storyteller information. No library state is written into
saved games, localStorage or sessionStorage.

Standalone category views use `/roles` with distinct logical history states;
characters retain `/roles/:roleId`. The router accepts optional history metadata.
Because the snapshot is associated with the history entry, the audience boundary
can remount the routed subtree without losing the browsing session. The category
cache also retains positions and last-viewed characters across category switches.

Category switches replace the current category entry. Character arrows replace
the current detail entry. Repeated selections are ignored; pending traversal
prevents repeated Back requests from consuming extra entries. Returning to a
category restores its exact scroll offset and focuses the last-viewed character
with `preventScroll`; a visible border and `aria-current` identify it.

Direct character links infer the correct script/category. They establish one
landing and one category parent before the detail entry, once, so native Back and
Forward have the same logical hierarchy as the visible controls. Normal remounts
and Forward navigation reuse existing entries. Entering from the main menu marks
the existing parent so leaving consumes that entry instead of pushing another
copy of home. A direct standalone landing uses home as a replace-only fallback.

## Public reference and privacy

PlayerReference still accepts only `scriptId` and the protected return callback.
It shares the same static catalog UI. Its logical entries keep the current game
URL; a capture listener handles its Back/Forward events before the router can
remount a privileged game screen. The nested rules sheet owns its own Back entry
and closes first.

Leaving from any reference view returns to the existing same-URL game anchor and
requests the shared handback screen. The Storyteller callback still requires the
continuous one-second hold. Forward during handback cannot reopen privileged UI.
Reload remains protected by the durable audience latch. The Spy's authorized
Grimoire view and game/save/PWA-update behavior are unchanged.

## Inventory and method

Reviewed all 894 paired EN/ES string leaves (75 line-type metadata leaves; 819 copy pairs) from 41 translation pairs: central translations, all 23 registered characters and all 17 registered effects. The central objects include the imported night-guidance and clarity strings. This is 82 paired translation source files plus the two shared bilingual modules, `nightGuidance.ts` and `clarity.ts`. 198 pairs changed or were added relative to baseline. Each pair includes both supported languages; no PT-BR was added.

[Full bilingual key-and-text inventory](UX_COPY_INVENTORY_W04.json) records every source, key and final English/Spanish text, including retained copy. The inventory is generated by evaluating static translation modules and traversing all leaves, not by counting only recently changed files. JSX text and literal accessible labels were scanned across production TSX. The only language-neutral JSX literals were a middle-dot separator and the assignment multiplicity “x”. Dynamic templates, translation fallbacks, date/time formatting and caller context were separately checked. New automatic game names now use EN/ES and explicit locale; saved names are unchanged. The English-only fallback for Other Players was removed.

## Spy root cause and fix

Reproduced in Chromium 149.0.7827.55 with Pixel touch emulation at 390×844 against the publicly deployed W03 baseline: tapping a Grimoire player produced no visible detail during the private session; the selected modal appeared only after Continue and successful protected handback. The selected-player callback reached GameScreen’s GrimoireModal state while `showFloatingButtons` correctly hid the modal during `isPlayerFacing`.

Spy now owns list/detail selection inside `SpyGrimoireView`, mounted only in its existing protected PlayerFacingScreen. It renders actual character and readonly effect descriptions, including dead/drunk status, with no editor, mutation callback or shared modal state. Back returns to list; browser Back from the list requests protected handback. Continue unmounts secret content before the one-second hold; completion/save happens afterward. Public Player Reference remains a separate static catalog and cannot reach these details. No privacy gate was loosened. No engine, rule, save schema or saved player data changed.

## Deferred issues and limits

- Existing unused Washerwoman “no Townsfolk” and Investigator “no Minions” translation keys remain for compatibility; those paths are disabled (allowZeroResult is Librarian-only). They are inventory entries, not supported results.
- Missing legal registration choices or unsupported editions still require a Storyteller ruling. This editorial patch does not add or reconstruct mechanics.
- Legacy execution events without a recorded death boolean retain their execution message; no death outcome is guessed. Historical snapshots and names are not rewritten.
- Optional help/lore remains longer than in-play primary instructions. PT-BR remains Task 017. Physical Android confirmation is pending; Chromium emulation is reported separately.
- Locked dependencies were kept unchanged. npm ci reports existing dependency advisories; dependency upgrades are outside this release’s copy/navigation scope.

## Android acceptance checklist

1. Reopen the updated PWA, reveal five players and complete the one-second return hold each time.
2. Show Investigator information about Spy: names and Spy result visible immediately; optional reference does not say it is the Investigator’s ability.
3. As Spy, open two player details, return to the list, use device Back, and complete protected handback; no late modal or editing controls.
4. Verify green checked Voting differs from red Nominee; inspect a tie and insufficient votes.
5. End Day, compare execution/death history, reopen the save and reach Night 2 without private information on reload.
